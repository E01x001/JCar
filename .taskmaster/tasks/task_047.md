# Task ID: 47

**Title:** Design Firestore Schema for Vehicle Ownership Transfer

**Status:** done

**Dependencies:** 33 ✓

**Priority:** medium

**Description:** Design new fields for the `vehicles` and `consultation_requests` collections and define a new `ownership_transfers` collection in Firestore to support vehicle ownership transfer logic.

**Details:**

This task involves defining the new Firestore data structure. Update the existing `Vehicle` and `ConsultationRequest` interfaces/types (likely found in `src/types/index.ts` or similar schema definition file) to include the new fields. Additionally, create a new interface/type `OwnershipTransfer` for the `ownership_transfers` collection.
1.  **`vehicles` Collection Schema Update**:
    *   Add `currentOwnerId: string | null` to reference the UID of the current owner. This field should replace any existing `sellerId` concept if applicable.
    *   Add `ownershipHistory: Array<{ transferId: string; transferredAt: firebase.firestore.Timestamp; fromUserId: string | null; toUserId: string | null; transferType: 'sell_to_admin' | 'admin_to_buyer'; price: number; }>` to track all ownership changes. This array should grow with each transfer.
    *   Add `isAdminOwned: boolean` (default `false`) to indicate if the vehicle is currently owned by the admin. This should be kept consistent with the `admin_owned_vehicles` collection created in Task 33.
    *   Add `availableForPurchase: boolean` (default `true`) to control vehicle listing availability.
2.  **`ownership_transfers` Collection Schema Definition**: Create a new top-level collection `ownership_transfers`. Each document will represent a single transfer event.
    *   `transferId`: string (document ID, auto-generated by Firestore).
    *   `vehicleId`: string (reference to the `vehicles` collection document ID).
    *   `consultationId`: string | null (reference to the `consultation_requests` collection document ID, nullable as not all transfers originate from a consultation).
    *   `fromUserId`: string | null (UID of the user selling, null if sold by admin or initial admin acquisition).
    *   `toUserId`: string | null (UID of the user buying, null if sold to admin).
    *   `transferType`: 'sell_to_admin' | 'admin_to_buyer' (enum, based on the specific transfer scenario).
    *   `transferredAt`: firebase.firestore.Timestamp (timestamp of the transfer).
    *   `price`: number (the agreed-upon price for the transfer).
    *   `notes`: string | null (optional field for additional details).
3.  **`consultation_requests` Collection Schema Update**:
    *   Add `isOwnershipTransferred: boolean` (default `false`) to indicate if an associated vehicle's ownership has been transferred.
    *   Add `transferId: string | null` to reference the `ownership_transfers` document ID if a transfer occurred as part of this consultation.
Ensure all new fields are properly typed in the application's schema definitions (e.g., TypeScript interfaces). No data migration is required for this design task; focus solely on schema definition.

**Test Strategy:**

1. Utilize the Firebase Emulator Suite to define and simulate the new schema structures locally.
2. Manually create test documents in the Firestore Emulator for `vehicles`, `ownership_transfers`, and `consultation_requests` collections.
3. Verify that all new fields (`currentOwnerId`, `ownershipHistory`, `isAdminOwned`, `availableForPurchase` in `vehicles`; all fields in `ownership_transfers`; `isOwnershipTransferred`, `transferId` in `consultation_requests`) are present and accept the intended data types.
4. Create linked documents: a `vehicle` document, an `ownership_transfers` document referencing the `vehicleId`, and a `consultation_requests` document referencing the `transferId`. Confirm the conceptual relationships are sound.
5. Verify that `isAdminOwned` in `vehicles` can be set correctly to reflect admin ownership, considering its consistency with the `admin_owned_vehicles` collection.
